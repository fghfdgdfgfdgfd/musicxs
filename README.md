# Music (SoundCloud + رادیو)

وب‌اپ موزیک با بک‌اند پایتون (FastAPI + yt-dlp + SQLite). بدون API key.

## اجرا
    docker build -t music .
    docker run --rm -p 8080:8080 -v music-data:/data music
    # http://localhost:8080

سرور باید به اینترنت (soundcloud.com) دسترسی داشته باشد.

## Railway
ریپو را به Railway وصل کن، بعد در Settings > Volumes یک Volume با Mount Path برابر `/data` بساز
(وگرنه با هر دیپلوی دیتابیس پاک می‌شود و لیست‌ها دوباره ساخته می‌شوند).
فقط **یک** instance/worker اجرا شود، چون زمان‌بند ۳ ساعته داخل همین پروسه است.

## چطور کار می‌کند
- **Home**: هر ۳ ساعت لیست هر ردیف دوباره اسکرپ می‌شود و لیست قبلی در دیتابیس **جایگزین** می‌شود
  (اگر اسکرپ شکست بخورد لیست قبلی می‌ماند).
- هر روز ۸ ژانر تصادفی انتخاب می‌شود (+ ردیف‌های ثابت Top Hits و New Releases). ژانرهای روز قبل حذف می‌شوند.
- **Recommended for You**: برای هر پلی‌لیست کاربر یک ردیف جدا؛ از لیست «related» خود SoundCloud
  برای ۳ آهنگ آخر همان پلی‌لیست ساخته می‌شود، هر ۳ ساعت تازه و جایگزین می‌شود.
- **کاورها**: هر کاور فقط یک بار از SoundCloud دانلود و روی دیسک سرور (کنار دیتابیس، پوشه `covers/`) ذخیره می‌شود و با `/api/cover/<id>` و کش یک‌ساله سرو می‌شود. بعد از هر اسکرپ، کاور همه‌ی آهنگ‌های Home پیش‌دانلود می‌شود.
- **Home**: لیست‌ها از دیتابیس سرو می‌شوند (ETag → اگر تغییری نباشد 304) و مرورگر آخرین نسخه را در localStorage نگه می‌دارد، پس با باز کردن سایت فوراً نمایش داده می‌شود.
- **Search**: ژانرها از `/api/genres` (همان `GENRES` در scraper.py) می‌آیند؛ ژانر جدید = یک خط در همان دیکشنری.
- **More**: آخر هر ردیف Home یک کارت More است که کل لیست را باز می‌کند و با دکمه‌ی More از سرچ ادامه می‌دهد. نتایج سرچ هم صفحه‌بندی ۲۰تایی دارند (`/api/search?q=- **Search**: ژانرها از `/api/genres` (همان `GENRES` در scraper.py) می‌آیند؛ ژانر جدید = یک خط در همان دیکشنری.offset=`، تا ۱۰۰ نتیجه، با کش ۱۰ دقیقه‌ای).
- **پخش**: `/api/link/<id>` فقط لینک مستقیم CDN را (با yt-dlp) می‌دهد؛ صدا هیچ‌وقت از سرور رد نمی‌شود و مرورگر مستقیم پخش می‌کند. لینک‌های HLS با hls.js در مرورگر پخش می‌شوند.
- **دانلود**: `/api/download/<id>`.
- **Radio**: ایستگاه‌های رایگان (SomaFM، Radio Paradise، NTS) از `server/radio_stations.json`؛ بدون API.
  ایستگاه جدید = یک آبجکت جدید در همان فایل.

## تنظیمات (env)
`REFRESH_SECONDS` (پیش‌فرض 10800)، `DAILY_GENRES` (8)، `ROW_SIZE` (20)، `DB_PATH`، `SCRAPE_CONCURRENCY` (4)

## نکته
SoundCloud گاهی ساختارش را عوض می‌کند. اگر پخش/اسکرپ خراب شد، دوباره build کن تا آخرین yt-dlp نصب شود.

## صداها (UI sound)
`web/js/sfx.js` از lookmv منتقل شده: همه‌چیز با WebAudio ساخته می‌شود (فایل صوتی ندارد). کلیک دکمه‌ها و تب‌ها، کارت‌ها، بوکمارک/دانلود، پلیر (play/pause/next/prev/seek/volume/speed)، تایپ (هر کلید یک نت)، اسکرول (تیک + ضربه‌ی لبه)، ورود/ثبت‌نام/خروج/حذف حساب، خطا و هشدار، و منوها/دیالوگ‌ها.
- وقتی آهنگ پخش می‌شود صداهای UI آرام‌تر می‌شوند و تیک اسکرول قطع است (تایپ همچنان صدا دارد).
- خاموش/روشن: منوی پروفایل ← «Sound». ذخیره در localStorage با کلید `ms_sfx`.
- صدای جدید برای یک کنترل: در `route()` داخل sfx.js یا با `SFX("name")` در کد اپ.

## عکس ژانرها و کاور رادیو
`server/images.py`: برای هر ژانر یک عکس مرتبط و برای هر ایستگاه رادیو یک عکس **تصادفی** مرتبط با اسم/ژانرش از Wikimedia Commons
(بدون API key؛ در صورت شکست LoremFlickr) گرفته می‌شود، فقط یک بار روی دیسک (`imgs/` کنار دیتابیس) ذخیره و با `/api/img/genre/<name>` و
`/api/img/radio/<id>` سرو می‌شود. عکس رادیوها هر `IMG_RADIO_TTL` ثانیه (پیش‌فرض ۷ روز) دوباره رندوم عوض می‌شود.
عبارت جست‌وجوی هر ژانر در `GENRE_Q` و هر ایستگاه در `RADIO_Q` است؛ اگر عکسی مناسب نبود همان‌جا عوضش کن و فایل متناظر را از `imgs/` پاک کن.
در شروع سرور همه‌ی عکس‌ها در پس‌زمینه دانلود می‌شوند (چند دقیقه‌ی اول ممکن است بعضی کاشی‌ها هنوز طرح قبلی را نشان بدهند).
